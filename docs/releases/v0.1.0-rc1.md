## Scope

- Refactors database persistence behind a compatible `DatabaseService` facade.
- Adds a shared database context for SQLite connection state, serial access, schema flags, and reopen/wipe state.
- Splits database persistence into domain files for schema/migrations, activities/raw events, markers/spans, tags/rules, app mappings, health checks, and SQLite helpers.
- Keeps the existing public completion APIs, `DatabaseError`, migration behavior, and aggregation change notifications compatible.
- Separates unit-test and UI-smoke schemes so regular unit tests no longer build the UI automation runner.
- Prepares the release workflow and DMG script for a clean RC build with checksum output.

## Known Limitations

- This RC does not add or intentionally change the database schema.
- Development builds may be unsigned and notarization-free when signing or notarization credentials are not provided.
- UI smoke requires a dedicated macOS runner with Automation Mode enabled without per-run authentication.

## Rollback

- Do not overwrite user data during rollback. Back up `~/Library/Application Support/Chronicle/activity.sqlite` and its WAL/SHM sidecars before installing a previous build.
- Reinstall the previous stable DMG from GitHub Releases.
- If a candidate build is rejected, keep the generated DMG as an internal artifact and publish the blocker list instead of promoting the RC.
