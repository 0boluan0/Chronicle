# Chronicle v1.1.0

Status: Draft
Target date: TBD
App version: `1.1.0`
Build: `8`
Artifact tag/version: `v1.1.0`

## Highlights

- Reframes Chronicle around five durable main-window destinations: Pending Review, Timeline, Notes, Insights, and Export & Integrations, with the menu bar kept as a light controller.
- Turns local activity evidence into editable work blocks and immutable completed-review snapshots; reviewed history is not silently rebuilt.
- Encrypts the Chronicle archive and WAL with SQLCipher using a random 256-bit, device-only Keychain key, and fails closed on a missing/wrong key or unknown database file.
- Changes window-title capture from broad capture with exclusions to an explicit per-application allowlist; app-level evidence continues without Accessibility access.
- Exports completed-review Markdown through managed blocks, records each attempt in encrypted export history, and reports any file/history partial success without making review depend on export.
- Rebuilds each touched canonical `YYYY-MM-DD.md` from every current review-revision leaf for that day, excluding pending blocks and superseded revisions; template-based daily reports use the separate `YYYY-MM-DD-report.md` namespace.
- Allows users to delete raw evidence for a reviewed range while retaining its immutable review snapshot; Activity segments outside that range and adjacent snapshot provenance remain valid through additive split-lineage metadata.
- Checkpoints the active session every 30 seconds and closes it on normal quit, bounding abnormal-termination loss to the uncheckpointed tail instead of the full active interval.
- Preserves live window-title context for privacy filtering and tag rules.
- Makes database initialization and schema migration fail closed instead of continuing with a partial schema.
- Migrates a recognized plaintext SQLite archive atomically through `sqlcipher_export`, preserving committed WAL data and removing the owner-only plaintext recovery copy immediately after the verified encrypted replacement is installed.
- Serializes in-place and cross-directory migration attempts for the same target through one stable process lock. A stale observer validates a peer's completed encrypted archive as an idempotent success and cannot overwrite writes made by the winning migration.
- Coordinates the encrypted archive lifetime across Chronicle processes: local-data deletion fails closed before removing the archive, Keychain key, or local settings while another process still has the archive open, and can be retried after that process exits.
- Removes aggregation and report-generation data races covered by concurrent regression tests.
- Prevents spreadsheet formula execution when exported CSV files are opened.
- Escapes automatically captured fields as plain text in generated Markdown so window or app names cannot inject remote-resource markup into an external previewer.
- Isolates UI automation preferences and app data from a user's live Chronicle installation.
- Simplifies first-run and completes the Simplified Chinese app-filter translation.

## Data and Upgrade Behavior

- Continues the existing public version line from `v1.0.5` (build `6`) to `v1.1.0` (build `8`).
- Existing local activity, notes, tags, rules, and export settings remain in place.
- Existing plaintext databases are converted in place only after a separately encrypted replacement passes integrity checks; unknown or corrupt files are not rebuilt as empty databases.
- The sandbox-to-Application-Support database move exports directly into an encrypted temporary destination before atomic installation; a failed move does not replace the destination database and leaves the legacy source recoverable, while a successful verified move removes the old plaintext database and sidecars.
- Window-title schema migration retains rule tags, manual overrides, and effective tags.
- The encryption key is stored in Keychain as `AfterFirstUnlockThisDeviceOnly`. Application Support backups remain usable only for the same user on the same Mac while that key survives; copying the folder alone to another Mac is not a supported restore.
- Downgrading the database in place is not supported. Builds without SQLCipher cannot open the encrypted archive; quit Chronicle and restore a compatible pre-upgrade backup before reinstalling an older build.
- Markdown, CSV, diagnostics, and telemetry exports remain ordinary plaintext files outside Chronicle and must be protected separately.
- Managed Markdown coordinates with compatible editors and rejects detected conflicts and non-regular targets; users should pause an uncoordinated editor while exporting to the same file.

## Known Limitations

- Updates remain manual through [GitHub Releases](https://github.com/0boluan0/Chronicle/releases); Chronicle does not run a background updater.
- Window-title capture remains opt-in and requires macOS Accessibility permission.
- Chronicle does not yet provide portable encrypted-archive export/import, so the encrypted database cannot be moved to another Mac without its non-synchronizing Keychain key.

## Rollback

The previous stable build is [Chronicle v1.0.5](https://github.com/0boluan0/Chronicle/releases/tag/v1.0.5). Quit Chronicle before replacing the app. Because v1.0.5 cannot read the new SQLCipher archive, restore a compatible pre-upgrade plaintext backup before launching it; do not point v1.0.5 at the upgraded encrypted database.
